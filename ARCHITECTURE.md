# Архитектура Study RAG

## Компоненты

| Слой | Что | Где |
|---|---|---|
| Веб | Next.js 16 App Router: Server Components читают данные под RLS пользователя, Route Handlers — API, `proxy.ts` обновляет сессию и закрывает всё, кроме `/login` | `src/app`, `src/proxy.ts` |
| Ядро | чистые функции с тестами: разбор и маскирование при загрузке, схема и валидатор меток, батчи, слияние A/B/арбитр, каппа, чанки, поиск и ответ | `src/lib/ingest`, `src/lib/labeling`, `src/lib/rag` |
| БД | Supabase Postgres: таблицы, RLS, триггеры лимитов демо, RPC очереди и поиска | `supabase/migrations` |
| Фон | pg_cron раз в минуту → `POST /api/worker/tick` (Bearer-секрет из Vault) → разметка батчей и индексация; кнопки в UI запускают первый тик через `after()` | `src/lib/worker.ts`, миграции 2, 6, 8 |
| LLM | `chat()` / `chatStream()`: бесплатные модели OpenRouter одним запросом с запасными (`models`), при отказе — Cloudflare Workers AI; тайм-аут на шаг | `src/lib/llm.ts` |
| Эмбеддинги | Cloudflare `@cf/baai/bge-m3`, 1024 измерения → `halfvec(1024)` | `src/lib/rag/embed.ts` |

## Данные

```
datasets ─┬─ documents ─┬─ labels (каждый голос: A, B, арбитр, человек)
          │             └─ chunks (единица/часть, header из меток, embedding, tsv)
          ├─ rulesets (версии схемы и правил: draft → approved → archived)
          ├─ label_jobs ── batches (очередь: queued → running → done/failed)
          └─ questions (история, ответ, источники, 👍/👎)
```

- Метки — `documents.labels` (jsonb + GIN), поэтому схема разметки у каждого датасета своя; фильтр поиска — `labels @> {...}`.
- RLS: свой датасет — всё; демо-датасет — чтение всем вошедшим; `questions` — только свои. Батчи, голоса агентов и чанки пишет только сервисный ключ воркера.
- Лимиты демо — триггерами: 30 документов на датасет, 30 вопросов в сутки; одна активная разметка на датасет (частичный уникальный индекс); 3 запуска разметки в сутки (API).

## Очередь разметки

1. `POST /api/datasets/[id]/jobs` — только по утверждённым правилам (триггер), документы режутся на батчи до 10 штук / ~12 тыс. токенов.
2. Тик: `claim_batches(2)` (`FOR UPDATE SKIP LOCKED`, аренда 10 минут) → `runBatch`: A и B параллельно (разные модели, разный порядок документов) → валидатор → слияние → арбитр одним запросом по спорным → `labels` + `documents`.
3. `finish_batch` одной транзакцией: статус батча, счётчики задания, повтор до 3 попыток, закрытие задания; после последнего батча — сводка в `datasets.stats.labeling` (доли, каппа A/B, модели, токены).
4. Отмена — `label_jobs.status = canceled`: идущий батч доработает без записи итога, остальные снимет воркер.

## Ответ на вопрос

`/api/ask` (SSE): вопрос пишется в `questions` до вызова LLM (лимит демо срабатывает сразу) → переписывание запроса и автофильтры (значения только из словаря схемы) → эмбеддинг → `match_chunks`: вектор top-40 + FTS top-40 → RRF → 30 → (пусто с автофильтром — повтор без него) → rerank LLM 0–10 по 20 → top-6 с оценкой ≥ 4, иначе честный отказ с ближайшими документами → соседние единицы ±1 → генерация со сносками [n] стримом → запись ответа и источников.

## Бесплатные лимиты и как в них укладываемся

| Ресурс | Лимит | Решение |
|---|---|---|
| OpenRouter `:free` | 50 запросов в день, модели перегружаются | один запрос на батч для каждого разметчика; запасные модели; Cloudflare после OpenRouter |
| Cloudflare Workers AI | 10 000 нейронов в день | эмбеддинги всего корпуса ≈ 4 тыс.; LLM — только запасной путь |
| Vercel Hobby | функция до 300 с | короткие тики с бюджетом времени, большой датасет индексируется скриптом |
| Supabase Free | 500 МБ БД | `halfvec` вдвое меньше `vector` |

## Безопасность

Регистрации нет; пароль демо-пользователя — только на сервере. Секретный ключ Supabase — только у воркера и скриптов. ФИО, телефоны, почты и номера документов маскируются при загрузке, поэтому в LLM и в демо они не попадают. Права на RPC очереди и индексации отозваны у `anon` и `authenticated`.
