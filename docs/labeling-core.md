# Ядро разметки — критерии (TDD)

Код — `src/lib/labeling/`, тесты рядом (`*.test.ts`; `*.critic.test.ts` — дописанные по критику тестов), номер критерия в имени теста. Запуск: `npm test`.

## Единицы (`units.ts`)
- U1 frontmatter между `---`: строки без кавычек, числа числом, `\\` → `\`, `""` → пустая строка.
- U2 нет frontmatter → `meta = {}`; пустой документ → нет единиц.
- U3 `## Слайд N` → slide, `## Страница N` → page (номер из заголовка); `## Раздел: X` → section, номер = порядковый номер единицы.
- U4 текст до первого заголовка → «Раздел: Вступление»; пустой — отбрасывается.
- U5 прочие заголовки (`###`, `## Другое`) остаются в тексте единицы.
- U6 пустая единица сохраняется с текстом `""`.
- U7 CRLF = LF.
- U8 `preview(units, max)` — «подпись\nтекст» по порядку, не длиннее `max`.
- U9 `estimateTokens` — 0 для пустого, ≥ длина/4, растёт с длиной.

## Батчи (`batching.ts`)
- B1 пусто → `[]`. B2 батч ≤ maxDocs и ≤ maxTokens (жадно по порядку). B3 документ больше бюджета — отдельным батчем. B4 порядок сохранён, каждый id ровно один раз. B5 maxTokens/maxDocs ≤ 0 или токены < 0 → ошибка.

## Схема и валидатор (`schema.ts`)
- S1 enum вне словаря → ошибка по полю, значение выброшено; text обрезается, не строка — ошибка.
- S2 нет обязательного (или null) → ошибка; не объект на входе → ошибка, не исключение.
- S3 необязательное может отсутствовать.
- S4 int: строка-число приводится; дробь, вне min/max — ошибка.
- S5 bool: true/false и «true»/«false»; прочее — ошибка.
- S6 лишние ключи выброшены, перечислены в `dropped`, `ok` не портят.
- S7 `parseFields` бросает на некорректной схеме: пусто, enum без значений, повтор ключа, ключ не snake_case, неизвестный тип, `allowedBy` на несуществующее поле.
- S8 `allowedBy {field, map}`: если значение родителя есть в карте, значение поля должно быть в списке; родителя нет в карте — без ограничений.

## Слияние (`merge.ts`)
Ключевые поля — `required` или `filter`. Значения A, B и арбитра сначала проходят валидатор.
- M1 ключевые совпали, обе уверенности ≥ порога, итог валиден → `agreed`; прочие поля от A, недостающие — от B. Совпали, но итог невалиден (нет обязательного) → `review`.
- M2 совпали, но уверенность ниже порога → `review`.
- M3 расходятся, арбитра нет → `needs_referee` + список спорных полей.
- M4 арбитр уверен и его значения валидны → `refereed` (спорное от арбитра, согласованное сохранено); иначе `review`.
- M5 нет одного из разметчиков → все ключевые поля спорные.
- M6 text сравнивается без регистра и пробелов по краям.
- M7 недопустимое значение = отсутствие; отсутствует у обоих — не спор.

## Каппа (`kappa.ts`)
- K1 полное совпадение → 1. K2 пример 20/5/10/15 → 0,4; случайное согласие → 0, хуже → < 0. K3 одна категория у обоих → 1 (без NaN). K4 разная длина или пусто → исключение. K5 симметрична, 3+ категорий.

## ПДн (`pii.ts`)
- P1 почта → `[почта]`. P2 телефоны +7/8 в любых записях → `[телефон]`; группы, годы, числа, ГОСТы не трогаются.
- P3 «Фамилия И.О.», «Фамилия И. О.», «И.О. Фамилия» → `[ФИО]`.
- P4 2–3 слова с заглавной после «Выполнил(а) / Подготовил(а) / Студент(а, ка) / Обучающийся(аяся)» и необязательных «студентка», «гр.», «группы», «№4107» (в том числе через пустые строки) → `[ФИО]`; само слово-ключ именем не считается.
- P5 фамилии из `keepNames` (преподаватели из схемы) не маскируются, с учётом падежа.
- P6 `piiFlag` = была хотя бы одна замена. P7 повторное маскирование ничего не меняет.
- P8 «им. А.Н. Туполева», «т.е.», «Рис. 1.» не маскируются. Большой вход (400 тыс. символов) — < 2 с.
