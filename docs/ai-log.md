## 2026-10-04 — Выбор темы и стека

**Инструмент:** Claude Code (Claude Opus).
> Запись восстановлена по заметкам 2026-10-11 — UNCONFIRMED, сверить с чатом от 04.10.

**Задача:** выбрать тему проекта OTUS, которая закрывает все требования курса и полезна нам самим, и подобрать стек.

**Промпт (суть):** дал требования курса (≥3 экранов, Postgres ≥3 таблиц, CRUD, auth, внешний API, деплой, CI/CD, Docker, тесты) и идею: ассистент по нашим учебным материалам КИ за 5 семестров, чтобы спрашивать «что было в лекции про семафоры» и получать ответ со ссылкой на слайд.

**Результат:**
- Тема: RAG-ассистент по материалам группы (лекции, методички, pptx, отчёты из Blackboard и Telegram).
- Стек: Next.js (TS, Tailwind) с API routes вместо отдельного бэкенда, Supabase (Postgres + pgvector + FTS russian + Auth + Storage), Vercel, GitHub Actions, LLM DeepSeek через OpenRouter.
- Таблицы: subjects → documents → chunks, плюс questions (история и фидбек).

**Проблемы и решения:**
- AI сначала предлагал упростить RAG до одного векторного поиска ради сроков. Отказался: качество ответа — главное в проекте. Оставили гибрид FTS + вектор + RRF, reranker, переписывание запроса, соседние слайды, честный отказ.
- Открытая регистрация не нужна и опасна: материалы закрытые. Решение — регистрация закрыта, три аккаунта создаются вручную, RLS.
- В первом варианте плана не было CRUD в UI, Dockerfile и журнала AI. Попросил AI сверить план с требованиями построчно и завести чеклист (теперь `docs/requirements.md`).

**Вывод:** AI хорошо собирает стек под требования, но сам склонен упрощать. Требования и «что не упрощать» надо фиксировать письменно в начале и сверяться с ними.

## 2026-10-11 — Инструкция для сбора данных через Codex

**Инструмент:** Claude Code (Claude Opus) пишет инструкцию; сбор выполняет Codex на компьютере одногруппницы.
**Задача:** собрать материалы за 5 семестров из трёх источников (Blackboard КИ, экспорт Telegram, «Загрузки»), убрать дубли, разметить и перевести в Markdown с точной нумерацией слайдов и страниц.

**Промпт (суть):** описать процесс так, чтобы человек без опыта мог запустить Codex одним сообщением, а Codex — пройти все шаги сам, останавливаясь на проверках.

**Результат:** `docs/data-collection.md` из двух частей:
- для человека: экспорт Telegram в JSON, вход в Blackboard, что разрешать и что нет агенту, что проверить;
- для Codex: рамки, структура папок, 11 шагов с точками «СТОП», формат Markdown (`## Слайд N` / `## Страница N`, `> [!image]` для картинок), `manifest.csv`, `questions.csv` (контрольные вопросы для eval).

**Проблемы и решения:**
- Каждый преподаватель раскладывает материалы в Blackboard по-своему, обход «по догадкам» пропустит файлы. Решение — сначала разведка DOM на одном курсе, потом исчерпывающая опись всех курсов и «СТОП 1» со сводкой «курсы с подозрительно малым числом файлов».
- Безопасность: агент работает в браузере с аккаунтом студентки. Решение — логин вводит человек сам, пароли и cookie в чат не просить, на сайтах только чтение, текст в материалах с «указаниями» считать данными.
- Eval-набор: вопросы от AI похожи на перефразированный слайд и завышают метрики. Решение — правила формулировок (разговорно, синонимы, вопросы через преподавателя или номер ЛР, вопросы «нет ответа»), колонка `keep` для ручной чистки.

**Вывод:** длинная задача для агента надёжнее с явным критерием готовности, файлами состояния и обязательными остановками на проверку человеком.

**Вывод:** с новыми версиями фреймворков агенту нужна документация той же версии, иначе он пишет код по устаревшим API.

Адаптив, пустые состояния и состояния загрузки.

**Проблемы и решения:**
- В Next.js 16 включены `cacheComponents`: страница документа с `params` не собиралась («uncached data during prerendering»). Решение — `generateStaticParams` по демо-документам.

- Переход по сноске через `next/link` не прокручивал к якорю слайда — заменили на обычную ссылку.

**Вывод:** прототип на моках даёт показать сценарий целиком до появления данных и БД; формы объектов в моках совпадают со схемой БД, поэтому в частях 2–3 меняется источник данных, а не экраны. Проверять глазами в браузере обязательно.

**Редизайн (тот же день).** Промпт: «задизайни не в стиле нейронки, на твоё усмотрение, но не базовый дизайн».
- Первая версия была типичной для AI: индиго-акцент, скруглённые карточки с тенью, эмодзи 👍/🖼. Выбрано направление «читальный зал» под предметную область: бумажный фон, чернила, красный «штамп» и жёлтый «маркер», засечки Literata + IBM Plex Sans/Mono (с кириллицей), линейки вместо теней, квадратные углы, сноски как в книге, римские номера семестров, номера слайдов на полях. Экраны переименованы: Вопрос, Указатель, Поступления, Журнал. Цвета — токены CSS с тёмной темой.
- Проверка в браузере (десктоп, 375 px, тёмная тема) нашла: автопрокрутку вниз при пустом чате (прятала фильтры), перенос текста в кнопке, «Выйти» за краем экрана на телефоне, сжатую колонку вопроса в журнале — исправлено.
- Вывод: «не как у нейронки» = отказаться от дефолтов (индиго, тени, скругления, эмодзи) и взять метафору из предметной области; дизайн-решения держать в токенах и общих классах (`globals.css`, `src/components/ui.ts`), тогда редизайн почти не трогает логику.

## 2026-11-07 — Этап 1: три варианта дизайна

**Инструмент:** Claude Code (Claude Opus 5.5).

**Промпт (суть):** «Три варианта HTML-моков — чат в три колонки с источником рядом + доска разметки; скриншоты сохрани для отчёта».

**Что сделал AI:** три самостоятельных мока на одних и тех же выдуманных данных (без материалов КИ): A «Консоль» (плотный, нейтральный, сетка батчей), B «Конспект» (мягкий, чат пузырями, канбан по статусам документов), C «Пульт» (контрастная сетка, ответ из пронумерованных утверждений, схема конвейера). У каждого — светлая и тёмная тема и вкладки вместо колонок на телефоне. 18 скриншотов в `docs/screenshots/design/`, описание и токены — `docs/design.md`.

**Проблемы и решения:**
- Headless Edge из песочницы не запускался, а в цикле кадры «пропадали». Настоящая причина нашлась при коммите: из-за экранирования `\$v` файлы сохранялись под именами `design$v-…png` рядом с папкой. Решение — скрипт `docs/design/shot.sh` на один кадр и вызов вне песочницы; локальные файлы во встроенном браузере не открываются — моки отдаются через `python -m http.server`.
- В варианте A сетка батчей на десктопе раздувалась (клетки `1fr` с `aspect-ratio`) — заменено на клетки фиксированного размера.
- Пользователь выбрал критерий «проще и быстрее сделать» → вариант A. Ирония: в редизайне 17.10 индиго и скругления были названы «дефолтом нейронки»; здесь их сознательно берём ради скорости, а характер даёт моно-шрифт для служебных данных и плотность доски.

**Вывод:** три мока на одних данных сравниваются быстро и честно; выбор лучше делать по стоимости реализации, когда все варианты приемлемы.

## 2026-11-07 — Ядро разметки через TDD с двумя критиками

**Инструмент:** Claude Code (Claude Opus 5.5) + два субагента-критика (Opus, чистый контекст).

**Промпт (суть):** «Ядро разметки без ключей через навык tdd-critic: разбор единиц, батчинг, валидатор схемы, слияние A/B/арбитр, каппа, маскирование ПДн».

**Что сделал AI:** критерии U1–P8 (`docs/labeling-core.md`) → 32 теста, падающие на заглушках → критик тестов → +24 теста (`*.critic.test.ts`) → код (`src/lib/labeling/`) → финальный критик кода → 17 регрессий (`final-critic.test.ts`) → исправления. Итог: 99 тестов. Прогон на всём датасете: 572 документа, 5 787 единиц (совпало с `units` во frontmatter у всех), ПДн найдены в 349 документах (863 ФИО, 69 телефонов, 120 почт), 0,5 с на корпус.

**Проблемы и решения:**
- Критик тестов: проверка min/max для семестра на деле срабатывала через зависимость «семестр ↔ предмет», а не через int; тест идемпотентности ПДн проходил на заглушке; не было поля «обязательное, но не фильтр». Дописано.
- Критик кода нашёл то, что тесты не ловили: поле `constructor` и значение `toString` брались из прототипа объекта (исключение), список преподавателей по префиксу фамилии оставлял открытыми студентов «Иванченко» при преподавателе «Иванов» — утечка ПДн; ряд чисел «8 128 256 32 64» маскировался как телефон; регулярка после «гр.» перебирала экспоненциально; BOM прятал frontmatter. Каждый случай — сначала падающий тест, потом правка.
- Живые данные дали шаблон, которого не было в критериях: «Обучающийся 4107 …» — добавлен.

**Вывод:** два независимых критика нашли разное: первый — слабые тесты, второй — дыры в коде на входах, которых в тестах не было. Для ПДн особенно важен второй: «зелёные тесты» не значили «нет утечки».

## 2026-11-07 — Офлайн-разметка основного датасета: архитектор, критик, разметчик A

**Инструмент:** Claude Code (Claude Opus 5.5 — архитектор и координатор) + субагент-критик (Opus, чистый контекст) + 29 субагентов-разметчиков (Sonnet, по одному на батч, до 4 параллельно).

**Промпт (суть):** «Разметь 572 документа КИ как разметчик A: входы через makeBatches и maskPii, правила v1 по стратифицированной выборке, критик на другой выборке, разметка субагентами с проверкой validateLabels, сводка и кандидаты в золотой набор. Агентам не показывать метки сборщика».

**Промпты агентов:**
- Критик: «Примени правила строго как разметчик к 20 документам, которых архитектор не видел; отметь противоречия, документы вне enum, места, где два добросовестных разметчика разойдутся, проблемы полей; дай точный текст правки». Результат — `data/labeling/critique_v1.md` (вне git: в нём фрагменты документов).
- Разметчик: `scripts/labeling/labeler-prompt.md` — читать только `ruleset_v1.json` и свой `inputs/batch-NNN.json`; не открывать `data/raw_*`, выходы других разметчиков, не запускать скрипты; на документ — `values`, одна `confidence` 0..1, `rationale` — 1–2 дословные цитаты.

**Что сделал AI:**
- `scripts/labeling/prepare.ts`: 572 документа → 29 батчей (≤20 документов, ≈63 тыс. символов), превью 3000 символов, sha256 как id; агентам уходят только имя файла, `source_path`, число единиц и превью.
- Правила v1 по выборке 30 (страты: папка семестра × источник × расширение × размер): 6 полей, 35 предметов + «другое», 12 типов документов (добавлены «статья» и «организационное» — в выборке были научная статья, ФОС, перечень лаб), карты «предмет → семестры» и «предмет → преподаватель» из subjects.csv.
- Критик: 16 замечаний, без проблем только 6 документов из 20; приняты все одной итерацией (детерминированный has_pii, карта преподавателей, «Часть N» только в названии курса, разведение ТЯП/МТ, ОП/ПОА, ИГ/КГ, порядок типов: конспект раньше отчёта).
- Разметка A: 572/572, 0 батчей с ошибкой формата (переразметка не понадобилась), 0 ошибок по значениям, средняя уверенность 0,856, ниже 0,7 — 87 документов (15,2 %). Типы: отчёт 47,6 %, лекция 12,2 %, методичка 10,3 %, конспект 7 %, статья 5,9 %. Семестр пуст у 17,5 % (по правилу «не угадывать»). has_pii = true у 73 %.
- Сверка с метками сборщика (только ориентир): предмет совпал в 331 из 336 случаев, тип — в 113 из 441: у сборщика нет «отчёта», лабы студентов шли как «задание».
- `gold_candidates.csv`: 80 документов: 20 с низкой уверенностью, покрытие 31 предмета и 6 редких типов, добор по полосам уверенности; меток A в файле нет, чтобы не подсказывать человеку.
